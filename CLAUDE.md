  path: /assets/img/[post-slug]-title.png
  alt: "Descriptive alt text for the hero image"

**Rules:**
- `image:` must be object form `{path, alt}` — never a plain string
- `categories:` must be a single value from the three allowed — never multi-word extra categories
- `canonical_url:` trailing slash is required; slug must match filename exactly
- Post byline at bottom must say "Associate Principal Engineer" — never "Senior Software Architect"

## Known Gotchas — Do Not Repeat These Mistakes

1. **`_includes/customize-head.html` does NOT inject into `<head>`** in this Chirpy gem version. Confirmed by live page inspection. Any code placed there is dead. Use `_includes/footer.html` for global injections instead.

2. **Category archives must stay disabled.** jekyll-archives was generating spurious thin pages (`/categories/distributed-systems/`, `/categories/quantum-communications/`, etc.) from over-categorized posts. These hurt GSC indexing. Categories are now disabled in archives config; only `[tags]` is enabled. Custom tab pages (`/computing/`, `/quantum/`, `/ai/`) serve the category landing page function.

3. **Do not add extra categories to posts.** Posts had categories like `[Software Architecture, Integration Engineering, Computing]`. Every extra category creates a new archive page. All posts now use only one of the three allowed category values.

4. **LinkedIn canonical URL.** The correct form is `https://www.linkedin.com/in/harshitj2005/` — with `www.` prefix and trailing slash. LinkedIn redirects the non-www version, but schema.org `sameAs` matching requires the exact canonical form.

5. **`image:` must be object form.** Chirpy and jekyll-seo-tag both require `image: {path, alt}` for proper hero image rendering and og:image output. A plain string `image: "/path/to/img.png"` may not render the hero correctly.

6. **Jekyll requires `YYYY-MM-DD-slug.md` filename format.** Posts without the date prefix do not get processed.

7. **Repo must be named `harshitj2005.github.io`** (not `harshitj2005`) for GitHub Pages to serve assets without a `/reponame/` baseurl prefix.

8. **GitHub Actions must be the Pages source** (not "Deploy from branch") to avoid the legacy `pages-build-deployment` runner conflicting with the custom workflow.

9. **`github-pages` gem cannot be used** — it locks Jekyll at 3.x and Chirpy requires 4+. The Gemfile uses `gem 'jekyll', '~> 4.3'` directly.
